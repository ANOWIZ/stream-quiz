# Викторина для прямого эфира

Полноценный MVP одной игровой комнаты: ведущий, до шести игроков, пять раундов и финал. Запуск разрешён с любым составом, включая одного игрока или пустую комнату. Русский интерфейс, серверные правила, Socket.IO, сохранение в SQLite, редактор контента. Зрители смотрят вашу трансляцию — отдельного зрительского подключения нет.

## Быстрый запуск

Требуется **Node.js 22.12+** и npm. На Windows используйте PowerShell; если выполнение npm.ps1 запрещено, замените `npm` на `npm.cmd`.

```sh
npm ci
npm run dev
```

Команда `dev` сама создаёт отсутствующий локальный `.env` со случайными паролями и SESSION_SECRET, генерирует Prisma Client, создаёт SQLite и запускает оба процесса. Пароли не выводятся в журналы: откройте локальный `.env` и передайте игрокам только PLAYER_PASSWORD.

- Ведущий: **http://localhost:5173/host**
- Игроки: **http://localhost:5173/play**
- С телефона в той же сети: `http://<LAN-IP-компьютера>:5173/play`. Разрешите вход на порт 5173 в Windows Firewall.
- Производственный сервер: те же `/host` и `/play` на вашем HTTPS-домене.

Ведущего и игроков для проверки открывайте в разных браузерных профилях / контекстах инкогнито. Вкладки одного профиля используют одну сессию игрока. Ведущий может открыть редактор в нескольких вкладках своей единственной сессии.

## Переменные окружения

Шаблон — [.env.example](.env.example). Настоящий `.env`, базы, загрузки, резервные копии и тестовые credentials исключены из Git.

| Переменная      | Назначение                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------------- |
| HOST_PASSWORD   | Отдельный пароль ведущего; обязателен                                                          |
| PLAYER_PASSWORD | Общий пароль игроков; обязателен                                                               |
| DATABASE_URL    | SQLite, по умолчанию `file:../data/quiz.db`; относительные пути считаются от каталога `prisma` |
| SESSION_SECRET  | Случайная строка минимум 32 символа, подпись HttpOnly cookie; обязательна                      |
| PORT            | Порт Node-сервера, по умолчанию 3001                                                           |
| NODE_ENV        | `production` включает Secure cookie; production требует HTTPS                                  |
| TRUST_PROXY     | `1` только при одном доверенном reverse proxy; иначе не задавайте                              |

Если `.env` уже существует, `dev` не перезаписывает его. Пустые обязательные значения нужно заполнить. SESSION_SECRET можно сгенерировать командой `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"`.

## База и контент

```sh
npm run db:generate
npm run db:push
```

SQLite-файл создаётся перед Prisma db push, включая Windows. В этой поставке есть **50 опубликованных вопросов и 30 связанных файлов** из библиотеки ведущего, включая восемь пользовательских фрагментов и две финальные панорамы — Венецию и Рио-де-Жанейро. При первом запуске с полностью пустой базой сервер импортирует их и создаёт пустое лобби. Вопросы, очки и файлы существующей установки не изменяются.

Набор хранится в `server/content/library/`: JSON содержит только вопросы, пакеты, категории, правила и зависимости медиа. В нём нет паролей, сессий, игроков, истории партий и черновиков. Файлы проверяются по SHA-256 и копируются в постоянный `uploads/`. Папка набора закрыта для прямой раздачи Vite. На новой установке выберите панораму финала вручную.

Чтобы подготовить новую версию набора из своей локальной библиотеки, выполните `npm run content:export` и просмотрите изменения перед публикацией. Экспорт читает рабочую базу и не сбрасывает партию. Без включённого набора приложение создаёт отдельный учебный пакет для проверки; тесты всегда используют изолированные учебные данные.

Перед стартом:

1. Войдите на /host. В **«Пакеты»** выберите учебный или соберите свой пакет с любым количеством вопросов в каждом раунде. В одной категории может быть несколько вопросов.
2. Нажмите **«Проверить пакет»**. Проверяются ответы, источники, шкалы, цитаты, медиа, кадрирование, страна и координаты панорамы. Требований к количеству вопросов и предупреждений о недостаточном банке нет.
3. Выберите пакет для партии. Панораму финала можно независимо выбрать в библиотеке кнопкой **«Использовать в финале»** до начала финала, включая паузу. Можно начать партию без выбора, но сам финал потребует выбрать панораму вручную. Панорама пакета служит доступным вариантом и не выбирается автоматически.
4. Нажмите **«Начать игру»** с любым числом подключённых игроков от 0 до 6; готовность не обязательна. Опубликованные правки вопросов автоматически обновляют библиотечные пакеты. При старте в SQLite сохраняется актуальная версия всего пакета. Правки банка после старта не меняют снимок первых пяти раундов; финальная панорама фиксируется при запуске финала.

Разделы ведущего:

- **Вопросы** — поиск, фильтры, создание, редактирование, дублирование, массовое включение/отключение, предпросмотр, импорт/экспорт JSON. Стоимость, сложность и порядок скрыты в форме; начисления задаются правилами раундов. Поле источника возвращено согласно актуальной версии правил.
- **Пакеты** — сборка, сохранение версий, проверка комплектности и выбор пакета.
- **Категории** — создание, переименование и удаление пустой категории.
- **Медиафайлы** — постоянная загрузка изображений и видео.
- **Финальные панорамы** — библиотека, интерактивный просмотр, координаты съёмки и ручной выбор.
- **Настройки** — названия раундов, очки, допуски и размеры загрузок. Названия можно менять во время игры, правила — в лобби. Количество заданий определяется пакетом. Начальные таймеры — 30 секунд для памяти и 60 для финала; оставшееся время ведущий может менять во время игры.
- **Игра** — партия продолжает работать независимо от открытого раздела. Редактор можно открыть отдельной вкладкой /editor.

Кнопка ведущего **«Предыдущий раунд»** возвращает к началу предыдущего раунда после подтверждения. Ответы и игровые начисления текущего и предыдущего раундов отменяются; более ранние очки и ручные поправки сохраняются. Карточки предыдущего раунда снова доступны. Архив начал раундов хранится в SQLite независимо от истории отмены. Для старых партий восстанавливаются доступные записи истории; если начала раунда в сохранении нет, кнопка недоступна. В новых партиях архив ведётся с первого раунда.

Неполные карточки автоматически сохраняются как **черновики в SQLite**; локальная копия формы есть и в sessionStorage. Они не входят в готовый пакет. Публикация выполняется отдельно кнопкой **«Сохранить вопрос»**. Текущий показываемый вопрос защищён от редактирования и удаления сервером. Остальной банк можно редактировать: начатая партия использует собственный снимок.

В «Угадай по фрагменту» загрузите оригинал, настройте рамку и нажмите **«Подготовить фрагмент»**. Сервер создаёт отдельный файл. До раскрытия игрокам выдаётся только он, полное изображение — после закрытия задания. Для «Запомни» загрузите изображение на сервер и добавьте один вопрос; время просмотра всегда 30 секунд.

### Импорт и экспорт

В рабочую библиотеку добавлен пакет **«Вопросы из 1.docx»** с вопросами ведущего и 26 изображениями. В «Угадай по фрагменту» восемь пользовательских карточек. Два ранее добавленных учебных фрагмента («Часы» и «Карандаш») удалены из этого пакета и сохранённой партии; исходные записи архивированы, очки сохранены. Перед новой партией откройте **«Пакеты» → «Вопросы из 1.docx» → «Выбрать для партии»**. Финальную панораму выбирайте отдельно.

Картинки взяты из папки `картинки для квиза`; фрагмент факела Статуи Свободы извлечён из DOCX. Оригинальные байты сохранены в `uploads`, включая изображения WebP с исходным расширением JPG/PNG (служебное расширение исправлено по фактическому формату). Эта папка исходников закрыта от прямой выдачи Vite. Пользовательский пакет хранится в SQLite, не добавляется повторно при запуске и переносится вместе с SQLite и `uploads` из резервной копии.

В «До и после» даты допускают год числом, строку `ГГГГ-ММ` или `ГГГГ-ММ-ДД`. Это позволяет сравнить два события одного года. До раскрытия обе даты скрыты по текущим правилам. При импорте готовой пары изображений фрагмента укажите `suppliedFragment: true`, отдельные `media.fileId` и `fullImageFileId`: повторная обрезка не требуется, полное изображение выдаётся только после раскрытия. Обычное кадрирование в редакторе продолжает работать.

Экспорт имеет формат:

```json
{
  "version": 1,
  "questions": [
    {
      "id": "example-number",
      "formatVersion": 2,
      "round": 1,
      "category": "Считаем",
      "text": "Сколько будет 12 × 12?",
      "answer": 144,
      "explanation": "Двенадцать дюжин.",
      "source": "Авторский учебный пример",
      "min": 0,
      "max": 200,
      "unit": "",
      "numericKind": "number",
      "active": true,
      "position": 0,
      "value": 100,
      "difficulty": 1,
      "alternatives": []
    }
  ]
}
```

Типы и схемы всех шести видов находятся в `shared/content.ts`. Импорт проверяется целиком и применяется одной транзакцией; существующие ID обновляются. Пустые/дублированные ID, отсутствующие ответы, недоступные медиа и неверные шкалы отклоняются. Экспорт содержит правильные ответы и доступен только ведущему. Экспорт JSON не включает бинарные медиа: для переноса всей установки используйте резервную копию.

### Изображения и видео

Загруженные файлы находятся в постоянном `uploads/`. Сервер генерирует имена и проверяет MIME, расширение, сигнатуру и размер. По умолчанию: изображение до 15 МБ, видео до 150 МБ; лимиты меняются в настройках. SVG принимаются только из собственного начального набора, загрузка произвольного SVG запрещена.

Можно выбрать загруженный файл, вставить HTTPS-ссылку на изображение / прямое MP4/WebM или ссылку YouTube. Задаются начало/конец видеофрагмента, звук и автозапуск. В актуальном пакете раунды 4 и 5 используют только изображения; видео можно добавлять к заданиям других раундов. Ведущий запускает, приостанавливает, перезапускает и останавливает видео. Состояние и позиция рассчитываются сервером; клиенты компенсируют загрузку и сверяют позицию. Браузер может потребовать один пользовательский клик для разрешения воспроизведения со звуком. Видео YouTube должно разрешать встраивание; внешняя доступность зависит от автора и видеосервиса.

Медиа раздаются через защищённый `/media/:id`, не как публичная папка. Игрок получает доступ только к медиа текущего вопроса в разрешённой фазе. В «Запомни кадр» во время просмотра в сетевом снимке нет текста вопроса; после просмотра сервер прекращает выдавать изображение игроку. Уже увиденные и загруженные браузером данные физически нельзя удалить из памяти участника.

## Локальные панорамы и финал

Финал работает без API-ключей и внешних картографических сервисов. `LocalPanoramaProvider` использует локально собранную Three.js (MIT): одно эквидистантное изображение на внутренней поверхности сферы, камера неподвижна. Перетаскивание и стрелки поворачивают обзор, колесо, жест двумя пальцами и кнопки +/− меняют приближение. Активных точек, ссылок и переходов между панорамами нет. Требуется браузер с WebGL.

Начальный поворот, наклон и масштаб, а также минимальное/максимальное приближение задаются отдельно для каждой локации. В предпросмотре можно повернуть камеру и нажать **«Использовать текущий ракурс»**. Масштаб задаётся множителем (1× — стандартный обзор); начальный масштаб должен лежать между пределами. Возвращение из карты сохраняет текущий обзор.

Контракт `PanoramaProvider` находится в `client/panorama-provider.ts`, реализация — `client/LocalPanoramaProvider.ts`, безопасный тип данных — `shared/panorama.ts`. Контракт позволяет добавить другого поставщика позже. Сейчас клиент использует только локальный файл, никаких SDK или ключей сторонних карт не загружает.

В банк включена настоящая 360° фотография **Kiara 1 Dawn**, автор **Greg Zaal / Poly Haven**, **CC0 1.0**. Она поставляется в `assets/panoramas/`, при создании базы копируется в приватный `uploads/` и доступна в библиотеке. Скачать её при запуске не требуется. Автор, источник и лицензия находятся в записи локации и [ASSETS.md](ASSETS.md). Правильная страна — Южная Африка; демонстрационная локация выбирается ведущим вручную.

Карта — локальные границы Natural Earth с ISO-кодами стран и территорий. Выбор по клику, с клавиатуры или через поиск; карта поддерживает масштаб и перемещение. Клик ставит личный пин в фактической точке выбора. Океан не считается ответом. Подтверждённая страна неизменна; через 60 секунд учитывается последний неподтверждённый выбор. Координаты съёмки проверяются по тем же границам и показываются отдельным пином при раскрытии. Засчитывается только точное совпадение страны. Ставки и ответы скрыты до раскрытия; URL файла выдаётся только с началом показа, название места, автор, источник, лицензия и правильная страна — при раскрытии.

## Правила и управление

Начальный счёт — 0, отрицательные очки разрешены, игроки не выбывают. **Количество вопросов свободное** и не зависит от числа игроков: раунд заканчивается после последнего задания пакета. В сохранённых партиях прежней версии используются все активные вопросы соответствующего раунда из банка, включая импортированные. Пустой раунд ведущий проходит кнопкой **«Пропустить пустой раунд»**. Финал остаётся одной вручную выбранной панорамой. Порядок выбирающих случайный, затем циклический и продолжается между раундами независимо от правильности ответа. Ведущий может изменить порядок и активного игрока. После раскрытия ведущий переходит к следующему вопросу; между раундами показывается таблица очков.

| Раунд               | Действие                                                                                                                                                         | Очки по умолчанию             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| Больше-меньше       | Активный игрок двигает целую отметку на основной круговой шкале и подтверждает. Остальные тайно выбирают «Больше», «Меньше» или «Столько же», затем подтверждают | +1000 за верный ответ         |
| До и после          | Обе даты скрыты; тайный выбор с подтверждением, после раскрытия видны обе даты                                                                                   | +1500                         |
| Кто это сказал?     | Тайный выбор одной из двух категорий; после раскрытия автор, произведение, источник и сведения о переводе                                                        | +2000                         |
| Угадай по фрагменту | Задания по категориям, отдельный фрагмент, первая серверная кнопка/Space и устный ответ                                                                        | +1000 / −500                  |
| Запомни             | Номерные плитки по числу заданий, изображение 30 секунд без вопроса, затем только вопрос и кнопка/Space                                                        | +1000 / −1000                 |
| География           | Тайная целая ставка, неподвижная 360° панорама, страна и личный пин за 60 секунд                                                                                 | Счёт + ставка / счёт − ставка |

В первом раунде для процентов используется шкала 0–100 и допуск ±5 процентных пунктов. Для остальных чисел T = abs(правильное число) × 5%. Граница включается: отклонение ≤ T означает «Столько же». Активный получает 1000 за попадание в допуск, каждый другой — 1000 за правильное сравнение. Значение T не раскрывается заранее; размеры допуска и очки редактируются в настройках.

В устных раундах первая полученная сервером заявка блокирует кнопки. После ошибки игрок больше не отвечает на этот вопрос, остальные могут нажать снова. Полное изображение возвращается только при закрытии. **«Отменить судейское решение»** отменяет конкретное судейское начисление и блокировку, сохраняя ручные поправки. Миллисекунды заявок доступны в закрытой панели.

Для этапов без заданного таймера скрытого отсчёта нет. **«Завершить ожидание»** требует подтверждения; отсутствующий ответ получает 0, отсутствующая ставка становится 0. Если активный не подтвердил число, вопрос приостанавливается; ведущий может передать ход.

Финальная ставка — целое число от 0 до всего положительного счёта игрока. Ограничение 50% удалено, в том числе для сохранённых партий прежней версии; уже подтверждённые ставки сохраняются. При нулевом/отрицательном счёте ставка 0. После ставок сервер ждёт готовности панорамы ведущего и игроков, затем запускает ровно 60 секунд. Ошибка загрузки приостанавливает отсчёт. Ведущий может явно продолжить без неготовых участников. Переключение между картой и панорамой сохраняет камеру, выбранную страну и пин. После подтверждения можно продолжать смотреть панораму. Новые локации «География» также дают 60 секунд при использовании в сохранённой партии старой версии. После всех подтверждений или окончания таймера сервер фиксирует ответы и ждёт кнопку ведущего **«Показать ответы»**. До нажатия страны, ставки и результат остаются скрыты, очки не начисляются; это ожидание сохраняется после перезапуска. Учитывается только страна: далёкий пин внутри неё верен, близкий за границей неверен. При равном максимальном результате объявляется совместная победа. Правильность страны показывается отдельно от ставки: неверный ответ со ставкой 0 остаётся неверным, но не уменьшает общий счёт. Итоговая карта расположена сверху по центру, под ней — топ-3 по общему счёту. На карте результатов страны нельзя выбирать, они не подсвечиваются при наведении. В правом нижнем углу карты есть кнопки увеличения, уменьшения, сброса масштаба и открытия на весь экран. Колесо мыши и жест двумя пальцами меняют масштаб, перетаскивание перемещает карту; с клавиатуры доступны +/−, стрелки и Home. В полноэкранном режиме можно подтвердить страну или вернуться к панораме; Escape сворачивает карту, сохраняя масштаб и выбранную страну. Увеличение и полный экран доступны также для карты результатов.

Управление ведущего:

- **«Следующий раунд»** с подтверждением пропускает остаток текущего. Начисления закрытых вопросов сохраняются; начисления незакрытого отменяются.
- **«Начать раунд заново»** с подтверждением сбрасывает вопросы, ответы и игровые очки текущего раунда. Предыдущие раунды и ручные корректировки сохраняются.
- **«Пропустить вопрос»** отменяет начисления испорченного вопроса и закрывает его.
- **«Пауза» / «Продолжить»** управляют серверным временем.
- **«Сбросить партию»** требует ввода СБРОС. Очищает прогресс и счёт, сохраняет банк и участников.
- Ручная корректировка счёта требует причину и попадает в журнал.
- После старта вход закрыт. Повторное подключение доступно по HttpOnly cookie; ведущий может открыть вход, новые игроки входят в очередь следующего раунда.
- **«Чистый экран»** скрывает навигацию и управление. Для безопасного захвата без закрытых данных используйте отдельный /obs; кнопка «Экран OBS» удалена из панели.

Все команды, фазы, таймеры и начисления проверяются сервером. Идентификаторы команд защищают от повторного начисления, в том числе после перезапуска. Обновление страницы восстанавливает сессию и актуальное состояние. Звуки отключаемые, конфетти только при победе, учитывается prefers-reduced-motion.

## Production и развёртывание

```sh
npm ci
npm run db:generate
npm run db:push
npm run build
npm start
```

Установите `NODE_ENV=production` и используйте HTTPS reverse proxy. Express раздаёт собранный React из `dist/client`, API и Socket.IO на одном порту. Запускайте **один процесс/одну реплику**: комната и очередь команд рассчитаны на одного владельца SQLite. Установка должна сохранять `data/`, `uploads/`, `backups/` и `.env` между релизами. Рабочий каталог — корень проекта.

Пример Nginx внутри HTTPS server-блока:

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 180s;
    client_max_body_size 160m;
}
```

Установите `TRUST_PROXY=1` для этой схемы. При увеличении лимита видео увеличьте и `client_max_body_size`. Не раздавайте `uploads`, SQLite, `.env` и `backups` напрямую через proxy. Проброс порта не заменяет HTTPS.

Включён Dockerfile. Сборка: `docker build -t ston-quiz .`. Пример запуска:

```sh
docker run --name ston-quiz --restart unless-stopped -p 127.0.0.1:3001:3001 --env-file .env -e NODE_ENV=production -e DATABASE_URL=file:/app/data/quiz.db -e TRUST_PROXY=1 -v ston-data:/app/data -v ston-uploads:/app/uploads -v ston-backups:/app/backups ston-quiz
```

Подключите HTTPS proxy. Получатся `https://quiz.example.com/host` и `https://quiz.example.com/play`. Docker-сборка предоставлена для развёртывания; основная проверка чистой установки выполняется локально через npm.

## Резервные копии и восстановление

Кнопка **«Резервная копия»** в банке вопросов создаёт `backups/<дата>-<id>/`:

- согласованный SQLite-снимок `quiz.db` через `VACUUM INTO` (контент, сессии, настройки, партия, история и журнал);
- копии всех файлов в `uploads/`;
- дополнительный `questions.json`.

Храните копию также вне сервера. Для восстановления остановите Node-сервер, сохраните копию текущих `data/` и `uploads/`, замените SQLite-файл файлом из backup и восстановите соответствующий каталог `uploads`. Используйте тот же SESSION_SECRET, если нужно сохранить существующие сессии. Запустите сервер снова; таймеры и фаза восстановятся. Не копируйте открытую SQLite вручную во время записи — используйте встроенный backup.

Если cookie ведущего потеряна, остановите сервер и выполните `npm run host:release`. Это удаляет только host-сессии из SQLite, сохраняя партию и игроков; после запуска ведущий сможет войти снова.

## Финальные панорамы: ручной выбор

Откройте **/host → Финальные панорамы**. Библиотека показывает превью, внутреннее название, страну, дату, активность и отметку «Использована ранее». История использования сохраняется между партиями.

1. Нажмите «Новая панорама». Загрузите JPG/JPEG, PNG или WebP либо импортируйте прямую HTTPS-ссылку. Нужна эквидистантная панорама всей сферы с пропорциями **2:1**, шириной **512–8192 px**. Размер ограничен настройкой загрузки изображений (по умолчанию 15 МБ).
2. Укажите внутреннее название, правильную страну, название места, пояснение, источник, автора, тип лицензии и HTTPS-ссылку на неё. Задайте начальный ракурс и пределы приближения. Укажите фактические широту и долготу съёмки: точка проверяется по локальной карте. Для небольших прибрежных островов, отсутствующих в упрощённых границах, координаты ведущего допускаются в пределах 10 км от ближайшей вершины береговой линии, если точка не попадает в другую страну. Проверка ответов игроков остаётся строгой. Перед запуском обязательны страна, координаты, источник и лицензия. Просмотрите панораму кнопкой «Интерактивный предпросмотр» и сохраните.
3. Нажмите **«Использовать в финале»**. Выбор виден в панели ведущего и сохраняется в SQLite. Выбирать и менять панораму можно в любой момент до запуска финала, в том числе на паузе. Она не обязана входить в выбранный пакет. Если выбора нет, перед финалом появляется ссылка на библиотеку. Автоматический случайный выбор отключён. Остальные вопросы библиотеки и пакета при выборе не изменяются.
4. Для замены после начала финала используйте **«Отменить финал и выбрать другую панораму»** с подтверждением. Ставки, страны и ответы этой попытки очищаются, её финальные начисления отменяются. Очки предыдущих раундов и ручные поправки сохраняются. Затем выберите панораму заново; ставки будут приняты заново.

Редактирование/удаление текущей локации блокируется на сервере до отмены финала. До показа игрок не получает файл, URL, внутреннее название, источник или правильную страну. В ходе партии выбранная версия локации защищена от незаметных правок банка. Каждая попытка имеет отдельный идентификатор; запоздалые команды отменённой попытки отклоняются. После начала финала для смены локации требуется явная отмена попытки, чтобы не восстановить старые ставки.

Импорт скачивает копию файла в приватный каталог `uploads/`. Поддерживаются прямые HTTPS-ответы HTTP 200 без redirect, с корректным MIME. Внутренние адреса, небезопасные порты и слишком большие ответы отклоняются. Исходный файл после проверки сохраняется без изменения байтов и без обрезки под случайным именем. Отдельная копия для просмотра — JPEG до 4096×2048 с сохранением всей сферы и без EXIF/XMP/GPS. Обе записи связаны в SQLite, сохраняются после перезапуска и входят в резервную копию. Удаление пары запрещено, пока любая её часть используется вопросом, черновиком или партией. Исходный файл и URL импорта не отправляются игрокам. Лимит загрузки меняется в настройках изображений. [Обработка метаданных Sharp](https://sharp.pixelplumbing.com/api-output/).

При обновлении старой установки внешние локации без локального файла автоматически отключаются, а их исходные записи архивируются в SQLite. Откройте такую запись, загрузите панораму и включите её. Начавшаяся попытка без локального файла возвращается к ручному выбору: ставки/ответы очищаются, общий счёт сохраняется. Завершённые результаты сохраняются. У существующих локальных панорам старый ракурс переносится в настройки локации.

Панорамы входят в JSON-экспорт банка (как вопросы round=6), а их файлы, выбор и история использования — в резервную копию SQLite + uploads. Существующая база обновляется без сброса партии и без изменения Prisma-схемы.

## Интерфейс по локальному эталону si-game

Перенесены исходные цвета, рамки игроков и ведущего, центральная сцена, доска с категориями по строкам, состояния кнопки «ОТВЕТИТЬ» и оформление редактора. Викторина сохраняет пять раундов, их очки и таймеры, тайные ответы, локальную панораму, SQLite и Socket.IO. Секретные вопросы, серии множителей и письменный финал из si-game не входят в правила этой викторины.

- `/` и `/play` — игрок.
- `/host` — ведущий. Основные действия снизу; кнопка с настройками справа в верхней строке открывает служебную панель, корректировку очков, журнал, порядок игроков и сброс.
- `/editor` — редактор с той же сессией ведущего. Вкладки раундов и блоки категорий, все прежние фильтры и операции; черновик сохраняется автоматически, публикация — кнопкой «Сохранить вопрос».
- `/obs` — чистая сцена для захвата окна браузера. Откройте в том же браузере после входа на `/host`. Это дополнительный экран ведущего, без зрительских аккаунтов и игровых команд. Скрытые ответы и заранее выбранная панорама не передаются. `/obs?sound=1` включает звуки; для звука браузеру может потребоваться первое нажатие в странице. Отдельный OBS Browser Source не разделяет cookie браузера: используйте захват этого окна, а не повторный вход второго ведущего.

Вход по-прежнему содержит только имя, пароль и кнопку. Пароли берутся из локального `.env`.

Кнопка ведущего **«Начать игру заново тем же составом»** доступна в нижней панели во время партии и после финала. После подтверждения сразу открывается первый раунд с нулевыми очками. Имена, цвета, сессии и порядок игроков сохраняются, включая отключившихся участников; повторный вход не нужен. Повтор использует прежние правила, актуальную опубликованную версию того же пакета и выбранную панораму. Если пакет удалён из библиотеки, используется сохранённый снимок. Ответы, ставки, таймеры и история отмены очищаются. Для смены пакета используйте обычный сброс в лобби. Если файлы пакета недоступны, повтор не запускается, текущая партия остаётся сохранённой.

Кнопка **«Завершить игру»** в нижней панели ведущего после подтверждения возвращает пустое лобби и открывает вход в новую партию. Все игроки отключаются и видят форму имени и пароля; отключённые от сети игроки получают её после восстановления связи. Можно снова войти с прежними именами: это будут новые участники с нулевыми очками. Ответы, ставки, таймеры, выбранная для партии панорама и история отмены очищаются. Ведущий остаётся авторизованным, библиотека вопросов, медиа, настройки и выбранный пакет сохраняются. Действие доступно на паузе и после финала; в уже пустом лобби кнопка отключена.

### Локальный запуск и откат интерфейса

Запуск: `npm run dev`. Ссылки: `http://localhost:5173/host`, `http://localhost:5173/play`, `http://localhost:5173/obs`, `http://localhost:5173/editor`.

До изменений сохранены client/server/shared/tests и документация в `.local/ui-reference-backup`. Чтобы вернуть предыдущую версию, остановите dev-сервер и выполните в корне проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .local/ui-reference-backup/restore.ps1
npm run dev
```

Скрипт восстанавливает исходные файлы; SQLite, загруженные файлы и `.env` не затрагиваются. Для запуска собранной версии после отката заново выполните `npm run build`. Добавленные CSS-файлы останутся неиспользуемыми.

### Названия раундов и обновление старой партии

Откройте **/host → Настройки → Названия раундов** и нажмите «Сохранить названия раундов». Имена сразу обновляются у ведущего, игроков и /obs и сохраняются в SQLite.

При обновлении старое лобби автоматически переводится на новые правила с архивом прежнего состояния в SQLite. Уже начатая старая партия сохраняет свои механики и очки. Ограничения количества вопросов сняты в обеих версиях. После сброса следующая партия использует выбранный пакет произвольного размера. Исходники и согласованная копия прежней SQLite дополнительно сохранены локально в .local/rules-v2-backup.

Если предпросмотр сообщает об ошибке загрузки, проверьте запуск npm run dev и нажмите «Повторить загрузку» либо «Обновить страницу». Партия и сессия сохранятся. Кеши тестов изолированы от рабочего Vite.

Первый раунд называется **«Больше-меньше»**. Каждая плитка подписана названием из первой колонки документа, одна плитка открывает один вопрос. Количество вопросов в категории на ней не показывается; использованная плитка сохраняет название, получает галочку и блокируется. Во втором и третьем раундах применяются такие же плитки. В раунде памяти кнопки подписаны «Запомни 1», «Запомни 2» и так далее без стоимости.

Для ранее импортированного `1.docx` выполнена одноразовая замена первого раунда: 10 вопросов «Фильмы», «География», «Космос», «Вода», «Россия», «Анатомия», «Музыкальные инструменты», «Планета Земля», «Животные», «Видеоигры». Тексты, ответы и шкалы взяты из первой таблицы. Старые вопросы первого раунда удалены из библиотеки и заменены в пакетах. Перед заменой создаётся SQLite-копия `backups/before-round-one-docx-*.db`. Состав игроков, очки, остальные раунды и выбранный финал сохраняются; открытый первый раунд возвращается к началу нового поля. Повторный запуск не восстанавливает удалённые вопросы и не перезаписывает последующие правки ведущего.

## Имя, результаты и допуск числового ответа

Игрок может нажать «Изменить имя» в верхней панели в любой фазе, включая паузу. Новое имя должно быть уникальным без учёта регистра и содержать 1–30 видимых символов. ID, место в очереди, цвет, ответы, ставки и очки сохраняются, новое имя восстанавливается после обновления и перезапуска.

В редакторе вопроса первого раунда задайте «Засчитывать от» и «Засчитывать до», например 190 и 198 при ответе 194. Границы включены, должны лежать внутри шкалы и содержать эталонный ответ. Число внутри диапазона получает полные настроенные очки, снаружи — 0. Оба пустых поля сохраняют прежний допуск раунда; в старой партии остаются ступени частичного зачёта и диапазоны остальных игроков. До раскрытия границы не передаются в игровой экран. «Сохранить вопрос» обновляет его копии в библиотечных пакетах, включая диапазон зачёта. Начатая партия сохраняет свой снимок; новые значения применяются при следующем старте или действии «Начать игру заново тем же составом». Кнопка «Показать ответ» раскрывает ответ сразу, без дополнительного диалога.

После раскрытия под пояснением игрок видит «Вы ответили верно», «Вы ответили неверно», «Вы не ответили» или «Частичный зачёт» и изменение очков. Оценка ответа не зависит от нулевой ставки или нулевой стоимости вопроса. Эталон на числовой шкале зелёный. Цвета игроков по местам входа: фиолетовый, голубой, розовый, оранжевый, белый, жёлтый.

Во втором и третьем раундах поле использует плитки с названиями, как первый раунд. В пятом — кнопки «Запомни 1», «Запомни 2» и т. д. без стоимости. Опорное событие располагается по центру; даты передаются только при раскрытии. Шапка содержит описание начислений из текущих настроек партии.

В журнале игры отображаются только фактические изменения очков с именем и знаком суммы. Журнал очищается при старте новой партии, повторе тем же составом, полном сбросе и завершении игры. Обнуление очков при новой партии не записывается как штраф. Во время одной партии переход между раундами сохраняет журнал; начисления, штрафы, ручные поправки и отмены записываются вместе с состоянием в SQLite. Перемещения отметки и прочие служебные действия туда не попадают.

В финале пауза останавливает только отсчёт: игроки могут сделать ставку, осматривать панораму, выбирать страну и подтверждать ответ. Загрузка панорамы также продолжается; когда она готова, игроки получают доступ без запуска времени. Все подтверждённые ответы остаются тайными до команды ведущего «Показать ответы».

Финальный таймер изначально равен **60 секундам**. Кнопка ведущего **«Изменить таймер»** заменяет оставшееся время любым целым неотрицательным числом секунд, без игрового верхнего лимита. Это изменение текущего отсчёта, а не настроек следующих вопросов. На паузе новое значение остаётся остановленным до «Продолжить», во время отсчёта сразу начинает убывать. Ноль завершает приём ответов сразу либо после продолжения, если эфир был на паузе. Изменение доступно и для других активных таймеров; уже завершённый вопрос оно не открывает заново. Состояние синхронизируется у всех участников и сохраняется при перезапуске.

Под картинками вопросов есть кнопка **«На весь экран»**. Каждый игрок и ведущий открывает просмотр только у себя: остальные экраны, ответы и таймер не меняются. Картинка показана целиком с сохранением пропорций; закрытие — кнопкой **«Свернуть картинку»** или Escape. В «Запомни кадр» окно автоматически закрывается по окончании просмотра, и картинка скрывается до раскрытия ответа. В «Угадай по фрагменту» до раскрытия увеличивается только разрешённый фрагмент. При смене вопроса полноэкранный просмотр закрывается. Прежнее общее растягивание, ползунок и сброс размера удалены.

В финале страну выбирают на карте без текстового поиска. Подписи игроков и правильного места отображаются шрифтом 18 экранных пикселей, независимо от масштаба карты; длинные подписи переносятся, положение ограничивается видимой областью.

По уточнению ведущего от 21.09.2026 игровая карта относит Крым, Донецкую, Луганскую, Херсонскую и Запорожскую области целиком к RU. Это пользовательская игровая схема, а не срез фактического контроля или международно признанных границ. Отображение и серверная проверка выбора используют общий `public/world.json`. Исходные полигоны, лицензия и воспроизводимая подготовка описаны в [assets/maps/README.md](assets/maps/README.md). Пересоздание карты: `node scripts/build-game-map.mjs`, проверка без записи: `node scripts/build-game-map.mjs --check`. После пересоздания перезапустите сервер и обновите открытые страницы игры; сама партия, вопросы и выбранная панорама сохраняются.
